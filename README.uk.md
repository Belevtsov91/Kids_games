# Interact Games

[Русский](README.md) · **Українська** · [Română](README.ro.md) · [English](README.en.md)

Ігри для дітей 3–15 років і кабінет для дорослих. Сайт чотирма мовами: російська, українська, румунська, англійська. pnpm-воркспейс: кожна гра — окремий пакет зі своїми залежностями, кодом, сервером і тестами. Спільні лише оболонка (`shell`) і невелика платформа.

## Що вміє сайт

- **Вхід батьків** і відновлення пароля поштою. Новий акаунт проходить «налаштування за хвилину»: дитина, час на день, PIN.
- **Профілі дітей.** Дитина обирає себе, а дашборд показує ігри за її віком, «Продовжити», план на сьогодні від дорослого, ведмедика Тьопу, сезонне оформлення і голосове привітання дорослого.
- **Режим малюка** (до 5 років або вмикає дорослий): без зайвих кнопок, а вихід із гри — утриманням кнопки 2 секунди. Змінити профіль чи відкрити кабінет без дорослого не можна.
- **Час:** денний ліміт, тихі години й перерви. Дитина може попросити ще часу, а дорослий відповість у кабінеті, кнопкою з листа або через помічника родини. За 2 хвилини до кінця гра дізнається про це й завершується м’яко.
- **Успіхи:** навички (лічба, кольори, фігури, пам’ять…), рівні й наліпки. Дитина бачить альбом наліпок, дорослий — навички кожної дитини.
- **Кабінет батьків** `/parent` (вхід задачею + PIN): огляд, профіль дитини, час, доступ до ігор, статистика, навички, зручність (гучність, менше руху, великі кнопки), галерея малюнків, план дня, прохання, помічники родини (бабуся відповість за своїм посиланням), листи й тижневий звіт, вивантаження даних, видалення акаунта.
- **Інші сторінки:** каталог ігор із картками (що розвиває, як грати разом), «Що нового», екран «немає мережі», сторінка 404.

Платних функцій поки немає.

## Стек

- **shell:** TypeScript, Vite, React, react-router, PWA (vite-plugin-pwa).
- **ігри:** будь-що на вибір гри: чистий DOM і Canvas, SVG, React, PixiJS + Howler (малювалка), matter-js (космічний садівник), Three.js + React Three Fiber + drei + Rapier (3D-ігри). Голос — Web Speech, звуки — Web Audio.
- **сервер:** Node 24, TypeScript, Fastify (запуск через tsx). Дані — у Supabase (Postgres); у кожної гри свої таблиці. Пошта — Brevo.
- **тести:** Vitest (юніт і API), Playwright (e2e, десктоп і телефон).

## Запуск

Потрібен Node 24+. pnpm іде через corepack, версію закріплено в `package.json`.

```bash
corepack pnpm install     # один раз і після додавання гри
corepack pnpm dev         # shell (http://localhost:5173) + сервер (http://localhost:3000)
corepack pnpm dev:shell   # лише клієнт
corepack pnpm dev:server  # лише API
corepack pnpm lint        # межі (ігри не імпортують одна одну) і розмір файлів (≤ 200 рядків)
corepack pnpm typecheck   # типи в усіх пакетах
corepack pnpm test        # юніт- і API-тести всіх пакетів
corepack pnpm test:e2e    # вхід, налаштування, меню → гра → вихід для кожної гри (Playwright)
corepack pnpm build       # lint + типи + збірка shell
```

Перед першим `test:e2e` один раз: `corepack pnpm --filter @ig/shell exec playwright install chromium`.

У dev Vite проксує `/api/*` на `http://localhost:3000`. Налаштування сервера: скопіюйте `platform/server/.env.example` у `platform/server/.env`.

### База даних

Створіть проєкт Supabase і заповніть у `.env` `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` і `SESSION_ENCRYPTION_KEY`. Без них сервер працює, але вхід відповідає 503, а API ігор — 401 (немає сесії).

Міграції платформи (`platform/server/migrations/001–006`) і всіх ігор збираються в один скрипт:

```bash
node tools/db-sql.mjs > all.sql
```

Вміст `all.sql` виконується в Supabase → SQL Editor. Скрипт ідемпотентний (`create … if not exists`): після нової міграції чи гри його можна просто виконати ще раз. Без міграцій 004 і 005 не працюють навички, наліпки, хмарні збереження, зручність, помічники, листи й план дня; без 006 — разова зміна профілю за PIN дорослого.

### Пошта

Листи (скидання пароля, прохання дитини про час із кнопками «Так/Ні», тижневий звіт) надсилаються через **Brevo**. У `platform/server/.env` задайте `MAIL_FROM_EMAIL` (відправник, підтверджений у Brevo → Senders) і один зі способів надсилання: SMTP (`SMTP_USER` вигляду `xxxx@smtp-brevo.com` і `SMTP_PASSWORD` — ключ `xsmtpsib-…`) або HTTP API (`BREVO_API_KEY` — ключ `xkeysib-…`). `APP_URL` — адреса сайту для посилань у листах. Ключі тримаємо лише в `.env` і змінних оточення хостингу, у git не кладемо.

Без пошти в dev сервер пише посилання для скидання в лог, а в проді (`NODE_ENV=production`) відповідає 503. Посилання для скидання одноразове й живе 30 хвилин, кнопки в листі про прохання — 24 години. Тижневий звіт надсилає фонова задача справжнього сервера (`server.ts`), у тестах вона не запускається.

### Продакшн

Клієнт — Vercel (`shell/vercel.json` проксує `/api` на сервер), сервер — Render. Змінні сервера в проді:

- `NODE_ENV=production`, `COOKIE_SECURE=true`, `APP_URL=https://ваш-домен`.
- `CORS_ORIGIN` — одна адреса або список через кому (наприклад, домен і прев’ю Vercel).
- `TRUST_PROXY` — скільки проксі перед сервером (типово 2: Vercel і Render). Від нього залежать IP у лімітах запитів.
- `CRON_SECRET` — вмикає `POST /api/jobs/hourly` (тижневі звіти) і `/api/jobs/daily` (прибирання) із заголовком `x-cron-secret`. Потрібен, якщо безкоштовний Render присипляє сервер: тоді внутрішні таймери не спрацьовують, і їх будить зовнішній cron.
- `VITE_API_URL` на Vercel не задаємо: запити йдуть на той самий домен через проксі, інакше cookie сесії стане сторонньою.

Сервер під час старту пише в лог, яких налаштувань бракує.

## SDK гри

Гра отримує від оболонки лише SDK:

| Поле | Що це |
|---|---|
| `manifest`, `profile`, `locale` | маніфест, дитина (або `null`), мова сайту |
| `api` | запити лише у свій префікс `/api/games/<id>` |
| `storage` | localStorage із ключами гри й дитини, копія в хмарі платформи |
| `cloud` | збереження на сервері платформи за дитиною (для ігор без свого сервера), до 64 КБ на ключ |
| `audio` | спільний вимикач звуку |
| `progress` | `level()`, `skill(skill, ok)`, `sticker(id)` — успіхи для альбому й кабінету |
| `time` | скільки лишилося та `onEnding()` за 2 хвилини до кінця |
| `comfort` | гучність музики й ефектів, менше руху, великі кнопки, режим малюка |
| `exit()` | повернутися в меню |

## Правила

1. Гра не імпортує іншу гру, `shell` чи `@ig/server`. Із платформою зв’язок лише через `@ig/sdk`. Це перевіряє `corepack pnpm lint`.
2. Shell і сервер не знають ігор за іменами: каталог збирається з маніфестів. Додали теку — гра з’явилася в меню та API. Видалили — зникла, решта працює.
3. `id` у маніфесті збігається з іменем теки. Зламаний маніфест не валить каталог: гра пропускається, помилка пишеться в лог. Навички й наліпки в маніфесті перевіряються.
4. Код, потрібний лише одній грі, живе в її теці. У `platform/` потрапляє лише те, що потрібно всім.
5. Сервер гри дізнається, чиї дані, лише із сесії: `childIdOf(req)` / `requireChild` з `@ig/sdk/server`. `profileId` із запиту не приймається.
6. У кожної гри свої таблиці `ig_game_<id>_*` (дефіси в id → `_`). Клієнт `opts.db` кидає помилку при зверненні до чужої таблиці, а lint перевіряє імена таблиць. Єдине посилання назовні — `child_id → ig_children(id) on delete cascade`.
7. Нові таблиці платформи — лише новою міграцією (`007_…`), потім перезібрати `all.sql`.

## API

Платформа (усі шляхи під `/api`):

| Метод | Шлях | Що робить |
|---|---|---|
| GET | `/health` | перевірка живості |
| POST | `/auth/register`, `/auth/login`, `/auth/logout` | вхід батьків; сесія — httpOnly-cookie |
| POST | `/auth/forgot`, `/auth/reset/check`, `/auth/reset` | скидання пароля через лист |
| GET | `/auth/me` | батьки, їхні діти й обрана дитина |
| POST, PUT | `/children`, `/children/active` | новий профіль, обрати, хто грає (при ліміті — лише з дорослим) |
| GET | `/games`, `/games/:id` | каталог ігор із маніфестів |
| GET, POST | `/kid/status`, `/kid/beat`, `/kid/requests`, `/kid/stats` | час, пульс гри, прохання, статистика |
| POST, GET | `/kid/progress`, `/kid/stickers`, `/kid/stickers/seen` | успіхи й альбом наліпок |
| GET, PUT | `/kid/cloud/:gameId/:key` | хмарні збереження гри (`null` видаляє ключ) |
| DELETE | `/auth/account` | видалити акаунт: відкритий кабінет і пароль |

| POST | `/answer`, `/helper`, `/helper/answer` | відповідь на прохання за посиланням із листа або від помічника |
| * | `/parent/*` | кабінет: вхід, огляд, діти, навички, прохання, помічники, листи, план дня, PIN, акаунт, `/setup`, `/export` |

## Дані в БД

Платформа: батьки й сесії, діти та їхні налаштування (час, зручність, план дня), час гри, прохання, події успіхів (`ig_play_events`), наліпки (`ig_stickers`), хмарні збереження (`ig_cloud_saves`), помічники родини (`ig_helpers`).

| Гра | Таблиця | Що в рядку |
|---|---|---|
| drawing | `ig_game_drawing_drawings` | малюнок: назва, PNG (data URL) |
| animal-orchestra | `ig_game_animal_orchestra_melodies` | мелодія: назва, ноти (jsonb); не більше 30 на дитину |
| island-builder | `ig_game_island_builder_islands` | острів дитини (jsonb), один на дитину |
| letter-eater | `ig_game_letter_eater_progress` | зірки за рівнями (smallint[]) |
| space-gardener | `ig_game_space_gardener_levels` | найкращі зірки за один рівень |
| who-lives-where | `ig_game_who_lives_where_progress` | рівень і знайдені звірі |
| moon-valley | `ig_game_moon_valley_saves` | стан долини (jsonb), один на дитину |

Усі таблиці закриті: RLS увімкнено, політик немає, права в `anon`/`authenticated` відкликано. Читає й пише лише сервер із секретним ключем. Репозиторій гри працює з БД, коли платформа передала `opts.db`, і з пам’яттю процесу без неї (тести, запуск без Supabase).
