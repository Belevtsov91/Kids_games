Автотест называется по ID кейса (`test('L5: …')`), поэтому кейс легко найти в отчёте Playwright.

## Как запускать

```bash
corepack pnpm test:e2e
```

Playwright сам поднимает Vite на порту 5174 и гоняет каждый тест на двух проектах: `desktop` (Desktop Chrome) и `phone` (Pixel 7).
Сервер API и Supabase не нужны: ответы сервера подменяет `shell/e2e/fakeApi.ts`. Поэтому тесты не создают аккаунтов, не шлют писем и не упираются в лимиты сервера.

## Приоритеты и риски

| Риск | Чем грозит | Приоритет | Чем закрыт |
| --- | --- | --- | --- |
| Сайт не открывается, пока сервер просыпается | Ребёнок видит пустой экран и уходит | Высокий | W1–W8, W10 |
| Сбой сервера посреди игры сбрасывает игру | Потерянный прогресс, слёзы | Высокий | W9 |
| Нельзя зарегистрироваться или войти | Новый взрослый не попадёт в продукт | Высокий | R1–R8, L1–L7 |
| Сообщения об ошибках вводят в заблуждение | Взрослый не понимает, что делать | Средний | L9–L11, R10, F4 |
| Восстановление пароля не работает | Потерянный аккаунт | Высокий | F1–F9 |
| Вёрстка ломается на телефоне или в другом языке | Плохое первое впечатление | Средний | W11–W12, P4–P5, L12, R9 |

## Что не автоматизировано и почему

- **F7: настоящее письмо через Brevo.** Проверяется только вручную: e2e не должны слать писем.
- **Серверные правила пароля и откат регистрации.** Это логика сервера, она закрыта юнит-тестами в `platform/server/tests/auth.test.ts`, а не e2e.
- **3D-анимация мишки и островов (как выглядит).** Проверяется глазами по скриншотам: пиксельные сравнения WebGL нестабильны.

## Тестовые данные

- В e2e всё вымышленное: `mama@example.com`, пароль `Correct-horse1` (`PASSWORD` в `fakeApi.ts`), токен сброса `RESET_TOKEN`.
- Для ручной проверки на локальном сервере использовать только адреса `@example.com`: локальный сервер пишет в настоящую базу Supabase и шлёт настоящие письма.
