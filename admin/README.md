# Пульт владельца (admin/)

Отдельный сайт только для владельца: мониторинг, журналы и простые исправления без захода в базу.
Живёт отдельным проектом на Vercel и ходит в тот же бэкенд на Render через `/api/admin`.
Основной сайт и игры не трогает: без `ADMIN_EMAILS` на сервере маршрутов `/api/admin` нет вообще.

## Что внутри

| Раздел | Что видно и что можно |
| --- | --- |
| Главная | семьи, дети, кто играет сейчас, минуты, топ игр, языки, возраст, устройства, просьбы, ошибки, письма; графики по дням |
| Здоровье | база, миграция, почта, игры, переменные, фоновые задачи (с ручным запуском), размер базы и бесплатные лимиты |
| Семьи | поиск, карточка семьи: изменить имя, почту, часовой пояс, язык писем; ссылка сброса пароля; сброс и разблокировка PIN; выход со всех устройств; выгрузка; заморозка; удаление через 7 дней с отменой |
| Дети | имя, возраст, вернуть из корзины, сбросить сохранение одной игры, фото и рисунки по кнопке (просмотр пишется в журнал) |
| Игры | минуты, игроки, верные ответы; выключить игру для всех |
| Письма | предпросмотр 5 шаблонов на 4 языках, тестовое письмо себе, журнал писем, повтор ссылки сброса |
| Ошибки | ошибки сайта и сервера за 90 дней, отметка «разобрано» |
| Безопасность | моя сессия, неудачные входы родителей, журнал моих действий (год), запуски задач; всё в CSV |
| Хранение | кто скоро удалится за неактивность (можно отложить), аккаунты на удалении, корзина профилей |
| Сайт | режим обслуживания, объявление для родителей, «Что нового», режим «только чтение» |

Опасные действия требуют слово (УДАЛИТЬ, ЗАМОРОЗИТЬ, СБРОСИТЬ, ВЫКЛЮЧИТЬ, ЗАКРЫТЬ) и код из приложения.
Лимиты, доступ к играм и ответы на просьбы админка не меняет: это решает только родитель.

## Заливка (один раз)

1. **База.** Собрать скрипт и выполнить его в Supabase → SQL Editor (он идемпотентный, добавляет миграцию 008):
   ```bash
   node tools/db-sql.mjs > all.sql
   ```
2. **Render** (сервис бэкенда) → Environment, добавить:
   - `ADMIN_EMAILS` — ваша почта (можно несколько через запятую).
   - `ADMIN_ORIGIN` — адрес админки на Vercel, например `https://kids-console.vercel.app` (без слэша в конце).
   - `ADMIN_SETUP_TOKEN` — длинная случайная строка, например из `openssl rand -hex 24`. Нужна только для первой настройки.
   - `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — для тревог и утренней сводки (бот через @BotFather, chat id через @userinfobot).
   - `CRON_SECRET` — если ещё не задан, любая длинная строка.
   - `SESSION_ENCRYPTION_KEY` должен уже быть (64 hex-символа): без него админка не включится.
3. **Vercel** → Add New → Project → тот же репозиторий, **Root Directory: `admin`**. Framework: Vite, остальное по умолчанию.
   Если адрес бэкенда другой, поменяйте его в `admin/vercel.json` (строка с `onrender.com`).
4. **Первая настройка.** Откройте админку → «Первая настройка или новый телефон». Введите почту, новый пароль (от 12 знаков)
   и секрет из `ADMIN_SETUP_TOKEN`. Отсканируйте QR приложением-аутентификатором и введите 6 цифр.
5. **Уберите `ADMIN_SETUP_TOKEN`** на Render (или поменяйте). Новый понадобится, только если потеряете телефон с кодами.
6. **Сторож** (`.github/workflows/admin-watchdog.yml`). В GitHub → Settings → Secrets and variables → Actions:
   переменная `API_URL` = `https://kids-games-api.onrender.com`, секреты `CRON_SECRET`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`.
   Каждые 5 минут он пингует сервер (и не даёт ему уснуть), запускает проверки и шлёт тревогу, если сайт лежит.
   GitHub запускает расписание только из основной ветки, поэтому сторож заработает после слияния.

## Разработка

```bash
cd admin
npm install
npm run dev:mock          # заглушка API с выдуманными данными на :3999
MOCK=1 npm run dev        # админка на http://localhost:5174 поверх заглушки
npm run dev               # или поверх настоящего бэкенда на :3000
npm test                  # словари 4 языков совпадают по ключам
npm run build
```

Защита: вход по почте, паролю и коду, сессия 8 часов, cookie только на `/api/admin`, блокировка после 5 ошибок с письмом,
письмо о входе с нового устройства, `noindex`, страница входа не называет проект, каждое изменение пишется в журнал.
