# Внедрение визуальной серии

Согласование: пользователь разрешил весь предложенный объём. Графика принадлежит каждой игре в `games/<id>/assets`; `visual-lab` не является runtime-зависимостью. Серверные контракты, манифесты и БД сохраняются. Большие иллюстрации экспортированы в WebP; персонажи, предметы и раскраски — SVG. Нынешняя заставка и GLB-модели Лунной Долины сохранены.

По уточнению пользователя линии раскрасок сохраняют исходную толщину. При подготовке файлов анализируется копия маски, обнаруживаются свободные концы и добавляются тонкие SVG-перемычки к ближайшему продолжению контура (до 14 пикселей при 1536×1024). Исправления записаны в `*-v4.svg` и игровые SVG; скрипт `tools/repair-coloring-pages.mjs` воспроизводит их через работающий Vite на 5173. Телефон получает готовые контуры без тяжёлого анализа при открытии. Сплошное расширение и морфологическое замыкание всего рисунка не используются. Это исправляет короткие разрывы; длинные художественные незамкнутые границы требуют отдельной правки. Видимая линия и граница заливки совпадают. При масштабе 100% лист вписывается в доступную область целиком.

Меню получает обложки через отдельный browser-only glob. Обновляются счёт, оркестр, все 37 животных и 8 домов, карточки питомцев и ресурсов, материалы острова, капли садовника, 11 изображений слов. В пазлы добавлены 4 местные иллюстрации. Новые виды животных — самостоятельные SVG-контуры в стиле одобренных персонажей.

## 1. Понимание системы
Детские игры с разными движками. Основной новый сценарий: открыть раскраску → выбрать цвет → залить/нарисовать → отменить → сохранить PNG в существующий альбом. Свободное рисование остаётся на Pixi; раскраски используют отдельный Canvas 2D с неизменяемыми линиями.

## 2. Риски
| Риск | Уровень | Влияние |
| --- | --- | --- |
| Выход теряет несохранённый рисунок | High | Потеря работы ребёнка |
| Линии стираются или заливка пересекает границу | High | Невозможно корректно раскрасить |
| Ошибка API показана как успешное сохранение | High | Пользователь считает работу сохранённой |
| Изображения ломают анимации/перетаскивание | Medium | Игровой сценарий становится неудобным |
| Большие SVG перегружают телефон/PWA | Medium | Медленная загрузка и кадры |
| Различные размеры SVG нарушают сетку | Low | Визуальные дефекты |

## 3. Решение о покрытии
Проверить заливку, отмену, сохранение/ошибку/повтор, защиту выхода, загрузку ресурсов, адаптивность и прежний запуск/выход всех игр. Не дублировать серверные CRUD/auth-тесты и не тестировать внутренности Three/Pixi. Геометрию статичных иллюстраций оценивать визуально.

## 4. Уровни
Unit: связная область, границы, повторная заливка, маска линий. E2E: один сквозной сценарий раскраски с настоящим Canvas, отменой, выходом и сохранением; это взаимодействие браузерных пикселей, React и API. Существующие unit/API и menu→game→exit проверяют регрессии. Дополнительно desktop/mobile визуальная проверка.

## 5. Данные
Чистый browser context на тест. Локальная фиксированная SVG-раскраска, синтетический профиль, перехват только API входа и сохранения. Первая запись отвечает 500, повтор — 200. Реальные учётные записи и БД не затрагиваются. Unit использует маленькие RGBA-массивы с известными контурами.

## 6. План и CI
Добавить unit в `games/drawing/tests/floodFill.test.ts` и browser flow в `shell/e2e/coloring.spec.ts`. Запустить typecheck, lint, существующие тесты, browser flow desktop/phone, production build. E2E использует текущую конфигурацию и её traces, без дополнительных зависимостей. Новый сценарий рассчитан на время до минуты на проект.

## 7. Надёжность
Ждать состояния загрузки, видимости и готовности кнопок; фиксированных задержек нет. Координаты Canvas вычислять по реально белому пикселю изображения и отображаемому размеру, а не по абсолютным координатам экрана. История ограничена 24 МБ и хранит только изменённые прямоугольники. Асинхронная загрузка освобождает обработчики при закрытии.

## 8. Проверка плана
QA governance: approved. Риски и уровни сопоставлены, API изолирован, бизнес-логика проверяется unit, браузер только для сквозного сценария. Селекторы по ролям/названиям, без sleep, проверки результата включают содержимое PNG и состояние сохранения. После реализации проверить отсутствие нестабильных ожиданий и утечек ресурсов.

## Результаты проверки
- Общий `pnpm test`: прошёл. После уточнения толщины линий drawing проверен отдельно: 20 тестов прошли.
- `pnpm build`: прошёл, включая изоляцию игр, TypeScript и PWA. Изображения включены в precache; тяжёлые SVG-обложки в сборку не попадают.
- Edge на существующем localhost:5173: сценарии меню → каждая из 10 игр → выход проверены на desktop и phone. Сбой от Vite HMR во время параллельного редактирования перепроверен отдельно — прошёл.
- Раскраски desktop/phone: заливка, точная отмена, подтверждение выхода через внутреннюю кнопку и ссылку оболочки, ошибка API и повторное сохранение PNG 1536×1024 — прошли. Анализ контуров перенесён из runtime в подготовку файлов, устранив медленное открытие на телефоне.
- 92 SVG в игровых assets разобраны XML-парсером; встроенного растра и скриптов нет. Все 6 игровых раскрасок содержат слой `contour-repairs`.
- Визуальная сверка меню, счёта, оркестра, миров, пазлов и раскрасок: ошибок JavaScript и незагруженных изображений не обнаружено. Снимки `preview-integrated-*.png`, данные `integration-check.json`.
- Реальная запись в Supabase в браузерном прогоне не выполнялась: API сохранения перехвачен; существующие серверные тесты прошли без изменений контракта.
